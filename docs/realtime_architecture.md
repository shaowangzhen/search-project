# 实时搜索架构设计

## 概述

实时搜索版本完全摒弃了数据存储依赖，每次搜索请求都会实时从6个搜索引擎获取结果，采用3秒快速响应策略：总超时2.5秒，单个请求1.5秒，确保整体搜索结果返回不超过3秒。

## 架构特点

### 1. 无存储依赖
- 不需要MySQL数据库
- 不需要Elasticsearch索引
- 不需要Redis缓存
- 完全基于实时搜索

### 2. 3秒快速响应策略
- **6个搜索引擎**：Google, Bing, DuckDuckGo, 百度, 搜狗, 360搜索
- **快速响应**：只取前3个最快响应的搜索引擎结果
- **超时控制**：总超时2.5秒，单个请求1.5秒
- **智能取消**：获得3个结果后自动取消剩余任务
- **目标**：整体搜索结果返回不超过3秒

### 3. 实时官方网站识别
- 基于多维度评分算法
- 实时内容分析
- 权威性验证
- 支持中英文官方网站识别

## 3秒快速响应策略

### 1. 超时设置
- **总超时时间**：2.5秒
- **单个请求超时**：1.5秒
- **目标响应时间**：不超过3秒
- **最大引擎数**：3个

### 2. 策略原理
- **并行启动**：同时向6个搜索引擎发送请求
- **快速收集**：收集前3个最快响应的结果
- **智能取消**：获得3个结果后取消剩余任务
- **时间控制**：严格控制在3秒内返回结果

### 3. 性能优化
```python
# 总超时时间控制
total_timeout = 2.5  # 总超时时间2.5秒
start_time = time.time()

# 单个请求超时控制
response_text = await asyncio.wait_for(task, timeout=1.5)

# 时间检查
if time.time() - start_time > total_timeout:
    print(f"⏰ 总搜索时间超过 {total_timeout} 秒，停止等待")
    break
```

### 4. 响应时间控制
- **单个请求超时**：1.5秒
- **总搜索时间**：2.5秒
- **目标响应时间**：不超过3秒
- **最快响应**：0.5-1.5秒获得结果

## 核心组件

### 1. 实时搜索服务 (RealtimeSearchService)

**功能**:
- 并行搜索6个搜索引擎
- 3秒快速响应策略执行
- 结果去重和合并
- 官方网站过滤
- 权威性评分排序

**关键方法**:
```python
async def search(query: str, max_results: int = 10) -> Dict[str, Any]
async def _fetch_results(session: httpx.AsyncClient, engine: str, query: str)
def _parse_results(html_content: str, engine: str) -> List[Dict]
def _is_official_website(link: str, query: str) -> bool
```

### 2. 搜索引擎解析器

**Google解析器**:
- 解析搜索结果HTML
- 提取标题、链接、摘要
- 处理Google重定向URL

**Bing解析器**:
- 解析Bing搜索结果
- 提取结构化数据
- 处理特殊格式

**DuckDuckGo解析器**:
- 解析隐私搜索引擎结果
- 提取干净的数据
- 处理无追踪格式

**百度解析器**:
- 解析百度搜索结果
- 处理中文内容
- 处理百度重定向链接

**搜狗解析器**:
- 解析搜狗搜索结果
- 提取中文网站信息
- 处理搜狗特有格式

**360搜索解析器**:
- 解析360搜索结果
- 处理中文官方网站
- 提取相关描述信息

### 3. 官方网站识别器

**多维度评分**:
- 域名权威性 (40%)
- 内容质量 (30%)
- 链接关系 (20%)
- 技术指标 (10%)

**实时分析**:
- 域名后缀检测 (.gov, .edu, .org, .gov.cn, .edu.cn)
- 内容关键词分析
- 结构化内容识别
- 技术指标验证
- 中文官方网站关键词识别

**中文支持**:
- 支持中文域名识别
- 中文关键词匹配
- 中文官方网站特征识别
